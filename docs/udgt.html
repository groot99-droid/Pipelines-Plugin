UDGT: UI, Dataset & Gameplay Teardown

A plugin that takes a game's repository apart. It records every design choice: what it is, how it was made, how it changed and what is planned next. It covers the frontend, the backend, the datasets, the gameplay, the world bible and the art pipeline. The owner takes part through a short creative brief before each chapter.

On this page: What it makes · Stages and briefs · The explorer · Who Did It · Using it · What it does not do

What it makes

  • A dataset, teardown.json: a graph of the game's numbered document sections, decisions and open questions, data records, code areas and ordered anchors (a phase machine, a tick order), protocol messages, design tokens, UI copy, screens, pull requests, commits and stated plans, linked by the citations between them.
  • Chapters, one per stage. Each choice is written up in three parts: Describe (with citations), Compare (with genre references) and Critique. Compare and Critique are labelled as Claude's analysis.
  • An explorer page that wears the game's own look.

Stages and briefs

A profile names the stages, for example: overview, UI, datasets, gameplay, backend, world, art and audio, history, future. Before each chapter, udgt.py brief gathers the stage's prompts and the gaps the scan found: open items, unresolved questions, and plans a later document withdrew. Claude asks the owner two to four questions, and udgt.py record keeps the answers verbatim in answers.json. Nothing else writes that file, and no answer is ever edited.

The explorer

udgt.py build themes the page from the game's design tokens and copies the font files the profile names. The title view is laid out like the game's main menu, and records are dealt as the game's cards. The page reads only the teardown's own JSON.

Who Did It

teardowns/who-did-it/ is the first teardown. It reads a sibling checkout of the game and never writes into it. The game's sessions reach it through the plugin's udgt-consult skill, and so do the render, sound and studio pipelines here when they work on Who Did It.

Using it

U="python plugins/udgt/engine/udgt.py"; P=teardowns/who-did-it/profile.json
$U scan  --profile $P        # read the game (sibling checkout, or --game)
$U check --profile $P        # broken citations, stale scan, chapter links; writes nothing
$U brief 3 --profile $P      # a stage's questions for the owner
$U build --profile $P        # then: python -m http.server --directory teardowns/who-did-it 8791
python -m unittest discover -s plugins/udgt/tests

Install it elsewhere with /plugin install udgt@rosw.

What it does not do

  • It never writes into the game's repository, and it runs none of the game's code.
  • It never paraphrases the owner, and it never presents its own critique as the owner's.
  • It copies nothing from the game except token values and the font files the profile names.
