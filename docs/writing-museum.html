Writing museum

A walkable 3D museum of the creative-writing vault, generated in the browser from data. A hall has a door to every work; behind each door is one room for that work, its passages hung on the walls as text panels, verbatim, and cited to their vault path and lines.

On this page: What it is · How a work becomes a room · Made through the studio · Viewing and building · What it does not do

What it is

It is fashioned after the Chronicle Museum of the author's Earth_Worldbuild repo, whose viewer (three.js, walk, look, doors, floor plan, go-to, guided tour, touch and gamepad) and layout builder (a salon-grid packer, a hall, a lint) were copied into this folder. What changed is what hangs on the walls: not paintings at their real size but passages of the author's own works, drawn as paper panels at a size that follows the text.

How a work becomes a room

  1. The work's own chunks (the ones vault_search.py cuts, and the chunk tagger tagged) become the panels. The transcription header above the text is left off; nothing in the text is changed.
  2. The work's mode picks the door theme and the frame styles. The mood tag that occurs most across its chunks picks the wall paint and the light; the motif tag that occurs most and has a row picks the floor and the trim. The table is writing-museum/build/mapping.json, and it is a reference, never binding.
  3. The scene spec, data/scenes/<id>.json, records the resolved values. The builder composes every spec into the manifest and the layout the viewer reads.

Made through the studio

A scene is made only through the studio's scene-3d pipeline (Studio → Pipelines). The author names the work at intake; the context stage attests the render and camera constraints; the recipe lists every value of the scene spec with its source; execute writes the spec, builds, and walks the room in a headless browser; review checks each output against each constraint and the vault's own rules; record leaves a note at studio/vault/<project>/3d/<id>.md. The notes are the point: a later 3D run recalls their decisions, and derives from them once there are three.

Viewing and building

python -m http.server 8768 --directory writing-museum     # then open /web/index.html
python writing-museum/build/build_museum.py build --lint   # the layout lint
python writing-museum/build/build_museum.py build          # write the manifest and the layout
node writing-museum/tools/walk_test.mjs                    # the browser walk-through
python -m unittest discover -s writing-museum/build/tests  # the builder's tests

The walk test needs Node, Playwright and Chromium; the build needs only Python.

What it does not do

  • It never writes into creative-writing/vault/. The 63 works stay verbatim.
  • It never writes a note itself. The studio run does, through content_md.py, after a preview and a yes.
  • A scene spec is not written by hand. It is a run's artifact.
  • There are no sculptures or models; the textures and the sky are CC0 (writing-museum/assets/CREDITS.md).
