Studio

Makes one thing at a time through six checkpointed stages. It leaves a note in its own vault that says how the thing was made, what is decided about it, and what happens next.

On this page: The rule · Stages · The ladder · Parking · Pipelines · Running it · What it writes · What it does not do

The rule underneath

Nothing is made before its context is resolved, attested and sourced.

Every constraint comes from somewhere you can point to: a brand gate the author wrote, a decision recorded in a past note, or a pattern across at least three past notes. If it comes from none of those, the studio asks you. If there is no answer, it parks the run. It does not guess, and it never fills a gap from general knowledge or from the design catalog.

The six stages

  1. intake
  2. context
  3. recipe
  4. execute go-ahead
  5. review
  6. record go-ahead
StageLeavesThe point
intakebrief.mdWhat is being made, in your words
contextattestation.mdEvery constraint it needs, and where each came from
reciperecipe.mdExactly what will be run, and the source of every value
executeexecute_log.md, artifactsRuns the recipe and nothing else. Needs your explicit go-ahead
reviewreview.mdEach output checked against each constraint
recordthe noteWhat was done, what is decided, what is next. Needs your explicit go-ahead

Every stage is a checkpoint: the skill stops, shows you the output, and waits. To redo a stage, the run goes back one stage at a time. Going back clears the go-aheads from there on.

Resolving context: the ladder

For each constraint, the context stage stops at the first level that answers it.

LevelResolves whenState
L0 authoredA brand gate in _Context/brand/ answers it, and does not list it as unresolvedresolved
L1 recalledA past note states it under Decisions in Force, quoted exactlyresolved
L2 derivedAt least three notes of the same kind imply it. Fewer is a coincidence, not precedentprovisional
STATEDYou state it at the checkpoint, with the dateresolved
L3None of the aboveunresolved: ask, or park

The attestation is one row per constraint, with its level and source. A run cannot leave the context stage with an unresolved row. The bookkeeper checks the record: that each cited file, section and quote exists. Whether a gate really says what a row claims is for you to read.

Parking

A run that cannot be grounded is parked. The note records which constraint is missing and what would resolve it, and its status becomes blocked. Anyone returning later can read why. Parking is a correct result, not a failure.

Pipelines

Nine are declared in studio/pipeline/spec.yaml, and seven are implemented. A pipeline that is not implemented is a real entry, saying what it needs and what is open, but it does not start.

PipelineMakesStatus
ui-directionA design direction for a surface or product, using the UI design plugin under the studio's brand gatesimplemented
ui-buildMarkup and CSS in which every value is a tokennot yet
brand-gateOne brand gate, transcribed from an interview with the authorimplemented
brushA brush and a Procreate file, through the designer and brush_pack.pypacker built; the app is still to be copied in
still-image, video-shot, music-cueThrough the Higgsfield connector; each spends credits after the execute go-aheadimplemented
edit-2dCopies of existing images, through the Adobe connectorimplemented
scene-3dThrough the Blender scene connector; a local Blender when the compute gate allows itimplemented (cloud branch)

Brand gates are the author's

The files in studio/vault/_Context/brand/, and tokens.json, encode taste and past decisions, which cannot be generated. A gate is written only by a brand-gate run: it is transcribed from what you say, and gate_md.py writes it only after you have seen the whole file and said yes. Anything else there is proposed as a diff, never written. The studio's own palette and typeface apply to the studio's own interfaces, not to client work: a client project's design system is its own authority.

Running it

Open Claude Code in the repo and ask for something, for example "a UI direction for our ops console". The studio-pipeline skill runs the stages. There is no standalone script, because the tools a stage calls exist only inside a live session. The skill runs these for you:

python studio/pipeline/studio_run.py new --pipeline ui-direction --title "Ops console"
python studio/pipeline/studio_run.py stage   <run-id>   # this stage's instructions
python studio/pipeline/studio_run.py facts   <run-id>   # what is on disk for each gate
python studio/pipeline/studio_run.py advance <run-id>   # mark done, if its checks pass
python studio/pipeline/studio_run.py status             # every run

python studio/pipeline/content_md.py plan  <run-id>     # preview; writes nothing
python studio/pipeline/content_md.py apply <run-id> --confirm

studio_run.py is a bookkeeper. It never calls a model or a tool; it keeps a run's state and refuses what the spec refuses. Exit codes: 0 done, 1 refused, 2 usage error. It needs pyyaml (pip install -r studio/pipeline/requirements.txt). The studio needs no API keys.

What it writes, and when

WhereWhen
studio/pipeline/runs/<run-id>/Freely. Bookkeeping, not tracked by git, safe to delete when a run is done
studio/vault/Only through content_md.py apply --confirm, after a plan and a go-ahead recorded after that plan
anywhere elseOnly in execute, only what the recipe named, only after a go-ahead

What it does not do

  • It does not read or write the creative-writing vault, unless you name a work at a checkpoint.
  • It does not generate a brand gate or change tokens.json.
  • It does not edit the UI design plugin; it runs that plugin's scripts.
  • It calls no connector tool that shares, publishes, invites or deploys.
  • It cannot stop a tool being called outside a pipeline. A pipeline is entered by choice. The bookkeeper can refuse to record a stage as done; it cannot refuse a tool call.
  • It does not know whether you reviewed a stage. It records a go-ahead on the skill's word.

Checking it

python -m unittest discover -s studio/pipeline/tests
python studio/pipeline/content_md.py lint --all

The rules in full are in studio/vault/CLAUDE.md, which is authoritative.
